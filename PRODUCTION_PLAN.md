# Production plan

For a scraper producing around 200 records a day, I'd keep the infrastructure simple and cheap. My starting point would be a $12/month DigitalOcean Ubuntu Droplet (2 GiB RAM), running the scraper, a FastAPI backend, and PostgreSQL through Docker Compose. One server is easy to reason about and debug; there's no need to add complexity before it's earned. I'd put Caddy in front as the web server and reverse proxy — it handles HTTPS certificates automatically, which removes an entire category of operational headache. Only ports 80, 443, and a restricted SSH port would be open to the internet; PostgreSQL stays private on the internal network.

For the database, PostgreSQL would store each casino's bonus history with a new versioned row per day, so you can see how offers change over time. I'd use a composite unique key on casino name, source URL, and date to make the scraper safe to retry — running it twice on the same day produces one record, not two. Nightly `pg_dump` backups would go to a private DigitalOcean Spaces bucket, keeping 30 days of copies and running a restore drill monthly to make sure the backups actually work. The single-server design is a deliberate trade-off: it's a known failure point, but it's acceptable at this scale. If uptime requirements tighten, moving to a managed database is a straightforward upgrade.

The scraper would run on a systemd timer at 02:00 UTC every night. A file lock would prevent two instances from running at the same time. If a run fails partway through, the previously published data stays untouched — readers always see the last successful result with a visible freshness timestamp rather than a broken or half-updated page. LLM output gets validated against the raw scraped evidence before anything is published, the same way the current script works. Transient failures get a bounded exponential backoff retry; anything that looks like a structural change to the source gets flagged for manual review rather than silently skipped.

For monitoring I'd use a Healthchecks.io heartbeat — the scraper pings it on success, and if no ping arrives within the expected window an email alert fires. That catches both hard failures and silent hangs. On budget, I'd estimate roughly $25–35 a month: $12 for the Droplet, $2.40 for weekly server snapshots, $5 for object storage, $1–2 for a domain, and $5–10 for LLM API usage based on token counts from test runs. The LLM figure is an assumption to track against real usage rather than a fixed cost; taxes and overages would be on top.

Pricing checked 15 October 2026: [DigitalOcean Droplets and backups](https://www.digitalocean.com/pricing/droplets), [Spaces](https://docs.digitalocean.com/products/spaces/details/pricing/). Domain and LLM costs are estimates.
